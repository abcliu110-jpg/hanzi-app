## 4.1 待产品负责人确认

- 「成」的“一成（十分之一）”在数据里来历待查，计划不说“借声音”，改加角落小字“来历还没有定论”，与 B 类规则不完全一致。
- 各字删掉的冷僻或“待查”义项：上（上色、皇上）、下（下策、一下）、生（学生）、中（中暑）、年（年代）、出（一出戏）、家（儒家）、看（看病、试试看）、一（统一）、行（行业 háng：data 里引申来历为“待查”）、经（经营：来历待查）、去（相距/相去甚远：偏文言）、法（法术/魔法：来历待查）、主（本义例词“灯炷、一炷香”：偏文言，本义改在开场讲）、理（本义例词“理玉、理璞”：偏文言，本义改在开场讲）、因（沿袭：因循、陈陈相因，偏文言）、说（劝说/游说 shuì：偏文言）。
- 「能」s1 本领：数据说《说文》以熊坚强称贤能、也有人认为借音，按数据类型（假借）作借声音段落并加“通行说法”角注，配音只说“‘能’被借来，表示本领”，请确认；开场“熊加上四点写成‘熊’”取自数据 codes。「而」3 个义项全是假借（而且、反而、自上而下），只在 s1 用喇叭 + 借声音标签，全片 63 s，少于“4–6 义项”；新线稿 anim/art/beard.json（下巴垂胡须的头像）。
- 「说」s6“高兴（古同‘悦’）”作借声音段落，例词用今字“喜悦”（板上写的是“喜悦”，不含“说”字），配音说明“后来另造了‘悦’字”，请确认；删去偏文言的 s5 劝说（游说 shuì）后讲 5 个义项。「你」数据只有 2 个义项（你好、你追我赶），全片 54 s，少于“4–6 义项”；开场不讲“尔”字本身的本义（数据说法不一），“借‘尔’的声音”为通行说法，加角注。
- 「来」开场的麦子复用线稿 rice（稻穗），画面上不太像麦，若要专门画麦子请告知；s1 借声音段落补了一句“借得久了，小麦就改写成‘麦’”（数据 why/codes 里的说法）。「地」s5 结构助词 de：数据原话是“借字形写虚词”，按 B 类规则仍用喇叭 + “借声音”标签，配音说“‘地’被借来，读轻轻的 de”，请确认是否改标签；s4 底色（白地蓝花）为通行说法，加角注。
- 「他」开场只说“古时候，‘它’字指的是蛇”“后来写成‘他’，先表示‘别的’”（通行说法，加角注），没有展开“无它乎”，也没有蛇的线稿；数据只有 3 个义项（其他、他们、睡他一觉），全片 60 s，少于“4–6 义项”。「个」s4“这”（个中，古诗借用，通行说法）作借声音段落，例词“个中滋味”今天仍用；s5 助词“说个不停”拼音按数据写轻声 ge，edge-tts 读音尚未人工听过；开场“箇”字只出现在字幕里，没有写在板上。
- 「有」s5 词头（有夏、有虞）是唯一的假借义项，偏文言，为保留 B 类借用段没有删，配音说明“今天，我们很少这样用了”，与「是」的处理相同，请确认；字源“手拿着肉”为通行说法（加角注）。「我」数据只有 3 个义项（自称·我们、我方·我校、自己·忘我），全片 60 s，少于“4–6 义项”；开场“像带齿刃的兵器”没有现成线稿，只圈字形、不画兵器。
- 首批 B 类「的」「是」：假借义项按设计用“喇叭线稿 + 借声音标签 + 日常句子”。「是」唯一的假借义项“这”（如是、由是）偏文言，为保留 B 类借用段没有删，配音说明“古书里……今天很少这样用”，请确认；判断词“是”由“这”变来是通行说法，已加角注。「的」s3 结构助词“借声音”数据为通行说法（加角注），s4“的士”为 taxi 音译（确定）。多音字 dì/dí/de/dī 由 edge-tts 读，尚未逐个人工听过（尤其“打的”“目的”“的确”）。
- 「因」删去偏文言的“沿袭”后只剩 3 个义项（依靠·因材施教、原因、因此），全片 64 s，少于“4–6 义项”；若要补回“因循守旧”请告知。「从」本义例句把“小鸭子跟鸭妈妈”改成“小鸡跟鸡妈妈”，以便复用线稿 hen。
- 「她」数据里只有 2 个义项（女性第三人称、指祖国/母校），按数据只讲 2 个，全片 53 s，少于“4–6 义项”的要求；“刘半农等提倡”是通行说法，动画只说“一百多年前，人们新造了这个字”，不提人名。

# 5. 制作经验（写脚本必看）

- **一只手画**：write/draw/path/circle/arrow 共用一支笔按时间排队。前一笔没画完，后面的 cue 会顺延，`snap.py` 报“cue 晚于关键词”。解决：缩短前一张线稿的 `dur`、`write` 用 `k≈1.0–1.7`、写字提前到句首。
- **写一个词要 3–6 秒**（笔画多更慢）。场景最后一句不要以正在写的词结尾，否则会画出场景外；画面需在场景结束前 200 ms 画完。
- `circle` 圈一张这个场景里还没画出来的线稿会直接报 TypeError（引擎待修，见 6）。
- 用 `on:` 贴附的线稿不参与重叠检查，要自己看 `snaps.jpg`。
- 3 个字以上的词会缩到 200 px 以下，不画下划线。
- 新线稿先查 `anim/art/` 有没有，重名不要覆盖。
- `circle` / `label` 的 `x y` 坐标是 1600×900 逻辑画布（不是 1920×1080）；圈田字格（GL）里字的右半边约 `x 530, y 405, rx 115, ry 175`。

# 6. 已知问题和风险

1. **配音授权**：edge-tts 没有商用授权，也可能失效。上线前换 Azure / 讯飞 / 火山或真人配音（也可评估开源可商用的 VoxCPM2）；只需在 `tts.py` 加 Backend，timeline 格式不变，然后全部重跑 `tts.py` + `mix.py`。
2. **笔画数据授权**：Arphic Public License，随应用附 `ARPHICPL.TXT`。
3. **引擎小问题**：circle 指向未画出的线稿会崩溃（应改成警告）；个别字混音后 mp3 比 timeline 长几秒（上：84.7 s vs 78.0 s），原因未查。
4. **楷体字体**：建议打包霞鹜文楷子集（OFL）。
5. **手的图片**是 AI 生成的，正式版建议换矢量手。
6. **提交方式**：GitHub Git Data API（blobs → trees → commits → 更新 refs）一次提交多个文件。Gitee 仓库停止更新，若 Gitee→GitHub 有自动镜像需关掉，否则可能覆盖 GitHub 上的提交。（2026-10-31：沙箱里 `git push` 拿不到凭据，`git pull`/`fetch` 正常；做法是本地正常 commit，再用 Git Data API 把 `origin/master..HEAD` 逐个重放成远端提交并 `reset --soft` 到远端。另：沙箱里 edge-tts 要去掉 HTTP(S)_PROXY 环境变量才能连上；Playwright 需先 `apt-get install` libatk 等系统库。）
7. 仓库 CI 是 GitHub Actions，迁到 GitHub 后会自动跑，新增的动画检查要保证能通过。

## 7.1 每个字的制作流程

1. `python3 tools/anim/draft.py 字` 出初稿；改写文案（每句 ≤25 字），按 A/B/C 和可信度规则处理。
2. 配 cue，复用线稿，必要时新增。
3. `tts.py 字` → `snap.py 字 --lines`（必须全过）→ 看 `.cache/anim/字/snaps.jpg` → `mix.py 字`。
3b. （2026-10-31 起）v2 验证：`python3 tools/anim2/test/determinism.py 字 --v1`（逐像素一致、iframe 无报错、警告 0）→ 看 `.cache/anim2/字/snaps.jpg` → `node tools/anim2/build.mjs --dist`（字体子集）→ `python3 tools/anim2/test/allchars.py` 全部 0 警告。
4. 脚本 `status` 设为 `done`；凑满 2 个字一起提交 GitHub master，同时更新本文档第 4 节进度。
