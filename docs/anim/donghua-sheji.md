# 1. 目标

每个字做一段**连续播放的白板动画**：一只手拿马克笔，配音讲到哪里就画到哪里，从字形、本义一路讲到各个引申义，最后收成一张关系图。它服务于 App 的学习路径「字 → 词 → 句 → 章」，放在“字”这一环，帮孩子理解**一个字为什么会有这么多意思**。

**不做的事**

- 不做“点一下走一步”。整段自动播放，只给暂停、重播、按章节跳转。
- 不做彩色插画或卡通角色（第二版已试过，确定不用）。
- 不把没有定论的字源讲成事实。
- 字义动画不负责教笔顺。关键字按真实笔顺书写只是画面的一部分；笔顺练习另做模块。

# 2. 风格规范（已定稿，以「节」白板版为准）

| 项 | 规范 |
|---|---|
| 画布 | 16:9，逻辑坐标 1600×900，纯白底 |
| 线条 | 主色墨黑 `#222`，线宽 5–7；手绘抖动滤镜（feTurbulence 0.03 + 位移 3.2） |
| 强调色 | 橙 `#F08A2C`（圈注、箭头、下划线，每个场景最多一处主强调），绿 `#3C9A5A`（字形部件），红 `#D9443F`（节日、警示），蓝 `#2F7FD0`（水、冷色物件） |
| 手 | 右手握马克笔 PNG，笔尖跟随正在画的路径；笔画之间抬笔走弧线；空闲 0.45 秒后移出画面 |
| 关键字 | 按真实笔顺逐笔书写（hanzi-writer-data 笔画 + 中线），大字 210–300 px，写完画一条橙色下划线 |

# 3. 叙事结构

每个字固定四段，顺序不变：

1. **开场·字形**：田字格里写出这个字；有繁体或老写法时在右侧写出并圈出表义部件（「节」→「節」的竹字头）。
2. **本义**：画出本义对应的实物或动作，圈出关键处，写出本义词。
3. **引申链**：按数据里 `senses[].from` 的树逐个讲。每段一句“为什么”（取自 `why`）+ 一个例词。相邻两段用画面上的同一元素过渡（竹节 → 骨节，竹节分段 → 一节课）。
4. **回顾**：中间写本义，向外画出各个意思，形成关系图。

## 3.1 按义项类型选场景模板

| `type` | 画面套路 | 配音句式 |
|---|---|---|
| 本义 | 画实物/动作 → 圈出 → 写词 | “……的地方，就叫……” |
| 引申 | 同一元素变形或移位到新场景，箭头相连 | “因为……，所以……也叫……” |
| 比喻 | 左右对照：左旧物、右新物，中间写“像” | “……像……，所以叫……” |
| 转喻 | 局部放大代表整体（头 → 一头牛） | “用……来代表……” |
| 假借 | 写出字，旁边画一个喇叭 + “借声音” 标签，再接一个日常句子 | “这个字的声音被借来，表示……” |

## 3.2 字源可信度规则（必须遵守）

数据字段 `origin.conf` 和 `senses[].conf`：

| 可信度 | 怎么讲 |
|---|---|
| 确定 | 正常讲，可以说“最早的意思是……” |
| 通行说法 | 可以讲，画面角落加小字“通行说法” |
| 待查 | **不讲字源**。开场直接写字 + “这个字最常用的意思是……”，画面角落小字“字源还没有定论” |
| 未标注 | 当“待查”处理 |

# 4. 首批 100 字

## 4.1 选字规则

按现代汉语字频（Jun Da, Modern Chinese Character Frequency List，美国中田纳西州立大学发布）取前 100 个。100 个字全部在仓库 3,499 字的数据里，共 512 个义项，平均每字 5.1 个（最少 2 个，最多 8 个）。

本义可信度：**确定 43 个，通行说法 47 个，待查 10 个**。义项类型：本义 100、引申 294、比喻 44、转喻 26、假借 50。

## 4.2 三种开场

| 类型 | 判定 | 数量 | 字 |
|---|---|---|---|
| A 字源 + 引申链 | 本义非待查，且没有假借义项 | 60 | 一在人中上大为和国到以时要就出会可对生得下自年过作用行家种事多经去法学同现当没动起看定天分还进好小主理心她本前开因从想实 |
| B 字源 + 借用段 | 本义非待查，有假借义项 | 30 | 的是有我他个来地说你能而子那之发后里道然成方如都面其些样但只 |
| C 无字源开场 | 本义为待查 | 10 | 不了这们也于着所么部 |

判定由脚本自动完成，制作时人工复核。像「在、为、以、就、可」这类虚词按规则落在 A 类，但最常用的意思很虚；建议先讲日常用法，字源放在开场一句带过，不展开画。

## 4.3 制作顺序

先做 A 类里画面最好表现的 20 个（人 大 上 下 中 天 小 心 生 年 家 出 开 本 前 看 动 学 好 分），用来打磨模板和线稿库；再做其余 A 类，然后 B 类，最后 C 类。完整清单见附录。

# 5. 数据设计

## 5.1 动画脚本：`anim/<字>.json`

一个字一个文件，由脚本从 `data/zi-<批>.json` 生成初稿，再人工修改。

```json
{
  "zi": "头",
  "version": 1,
  "group": 1,
  "track": "A",
  "voice": { "name": "zh-CN-XiaoxiaoNeural", "rate": "-6%" },
  "scenes": [
    {
      "id": "intro", "kind": "intro",
      "lines": [
        { "text": "这是“头”字。",
          "cues": [ { "at": 0, "do": "grid", "slot": "C" },
                    { "at": 0, "do": "write", "chars": "头", "slot": "C", "size": 440 } ] }
      ]
    },
    {
      "id": "h0", "kind": "sense", "sense": "h0", "type": "本义",
      "lines": [
        { "text": "我们身体最上面的部分，叫头。",
          "cues": [ { "at": 0, "do": "draw", "art": "person-head", "slot": "L" },
                    { "at": "头", "do": "circle", "target": "person-head.head", "color": "orange" },
                    { "at": "叫头", "do": "write", "chars": "头", "slot": "R1", "size": 280 },
                    { "at": "叫头+1.5s", "do": "label", "text": "tóu", "slot": "R2" } ] }
      ]
    }
  ],
  "recap": { "center": "脑袋", "nodes": ["h1", "h2", "h3", "h4", "h5", "h6"] }
}
```

**cue 时间写法**：`0` = 句首；`"关键字"` = 配音念到这个词的时刻（按字符位置估算）；`"关键字+1.5s"` = 再往后偏移。这样改配音后不用重新对时间。

**cue 动作**

| `do` | 作用 | 主要参数 |
|---|---|---|
| `grid` | 画田字格 | `slot` |
| `write` | 按笔顺写字（手跟随） | `chars` `slot` `size` `color` `underline` |
| `draw` | 画线稿库里的一张图（手跟随） | `art` `slot` `scale` `color` |
| `path` | 画一条自定义路径 | `d` `color` `width` |
| `circle` | 手绘圈注 | `target`（线稿锚点）或 `x y rx ry` |
| `arrow` | 手绘箭头 | `from` `to` `bend` |
| `label` | 淡入文字（拼音、词语、出处） | `text` `slot` `size` `color` |
| `note` | 角落小字（通行说法、字源待考） | `text` |

**版位 slot**：`C`（居中田字格）、`L`（左区线稿）、`R1` `R2` `R3`（右区第 1/2/3 行）、`TL`（左上小卡）、`BR`（右下）。只在必要时写坐标。

## 5.2 线稿库：`anim/art/<名称>.json`

每张线稿是一组**单线路径**（中线，不是轮廓），在 400×400 的本地坐标里，按绘制顺序排列，可带锚点：

```json
{ "name": "bamboo-3", "strokes": ["M180 380 L182 260", "..."],
  "anchors": { "node1": [205, 260], "node2": [205, 140] } }
```

100 个字预计需要 120–150 张。可复用的基础件优先：人、手、头、眼、心、太阳、月亮、山、水、树、竹子、房子、门、路、箭头、钟、书、课桌、田、车。

线稿来源按优先级：① 在 Inkscape 等工具里手画单线路径；② 先出黑白线稿图，用 `autotrace -centerline` 转中线再人工清理。不要用填充轮廓直接描边，画出来是双线。

## 5.3 生成物

| 文件 | 说明 |
|---|---|
| `anim/<字>.timeline.json` | 每句配音的起点和时长（TTS 后生成） |
| `anim/<字>.mp3` | 混好的音轨：配音 + 笔声 + 翻页声 + 背景乐，约 64–96 kbps |
| `anim/index.json` | 已完成的字、时长、版本 |
| `exports/<字>.mp4` | 分享用视频（可选，不进 App 包） |

# 6. 播放器

- 从试点抽出一个通用引擎 `xzq-anim.js`：读 `anim/<字>.json` + timeline + mp3，按音频时间驱动画面（`render(t)` 是纯函数，可任意跳转，也用于逐帧导出视频）。
- 入口：`ziyi-viewer.html` 字义扩展图顶部加“▶ 看动画”，只在 `anim/index.json` 里有这个字时显示。
- 控件：播放/暂停、进度条带章节标记、0.75× / 1× / 1.25×、字幕开关。
- `prefers-reduced-motion`：不播放手和滑屏，直接逐段显示画好的静态板 + 配音。
- 进度：看完 90% 记入 localStorage `xzq_anim`（字 → 最后观看时间），学习路径可读取。
- 离线：PWA 不预缓存全部动画，打开过的字再缓存。

# 7. 声音

- **配音**：试点用的是 edge-tts（微软晓晓 zh-CN-XiaoxiaoNeural）。这是微软浏览器朗读的非公开接口，**不适合商用上线**。正式版换成有商用授权的服务：Azure 语音（同一个“晓晓”声音，按量付费）、讯飞或火山引擎，或真人配音。
- **笔声、翻页声、背景乐**：试点里用程序合成，无版权问题；正式版可换成正版音效库素材。
- 混音：配音响时背景乐压低约 −9 dB，整体 −16 LUFS，峰值 −1.5 dBTP。

# 8. 验收标准（每个字）

1. 配音每句不超过 25 个字，用词适合 6–9 岁。
2. 每个圈注、箭头、关键字都在配音念到对应词的 ±0.3 秒内出现。
3. 字源可信度规则全部遵守（第 3.2 节）。
4. 写字笔顺与 hanzi-writer-data 一致。
5. 画面不重叠、不出框，字幕不遮挡关键内容。
6. 全片无控制台报错；任意跳转后画面正确。
7. 总时长不超过 120 秒。
